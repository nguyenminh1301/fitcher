# Changelog

## Unreleased

### Added

- Sign in through one OpenID Connect provider in team mode (DECISIONS §9): an admin registers its issuer, client id, client secret (stored encrypted, shown only as its last four characters) and roles claim with `GET`, `PUT` and `DELETE /settings/oidc`, which checks the provider's discovery document before saving and records each change in `agent_logs.admin_actions` without the secret; `GET /session/oidc` tells the sign-in page whether it is on, `GET /session/oidc/start` sends the browser to the provider with PKCE (S256), state and nonce, and `GET /session/oidc/callback` accepts an ID token only when a key of the provider's JWKS signed it for this client, unexpired and with the nonce. The first sign-in of a subject creates an account with the claim's roles that exist in the instance (state change `0006_oidc.sql`), an e-mail another account uses is refused, and local accounts keep working.
- Serve one owner without sign-in in individual mode (DECISIONS §9): every request acts as the built-in `owner`, who holds every pack and console role; the api answers only when `Host` is a loopback name, a name in `FITCHER_ALLOWED_HOSTS` or one of `FITCHER_INTERNAL_HOSTS` (Compose sets `api`), checks the browser's host that the web server forwards as `X-Forwarded-Host`, and accepts a change only when `Origin` matches that host. `GET /me` adds `mode` and `exposed` (a non-loopback host is allowed). A new instance is individual until its setup chooses; `PUT /setup/mode` to team creates the first admin from the request with the owner's id, so the owner's conversations stay theirs, and signs the caller in; going back to individual is refused while more than one account is enabled. `X-Forwarded-Proto` marks the session cookie `Secure` only when `FITCHER_ALLOWED_HOSTS` is set.
- Sign in with an account kept by the application: the app state gains `accounts`, `account_roles`, `account_sessions` and `sign_in_failures` (state change `0005_accounts.sql`); passwords are hashed with Argon2id at argon2-cffi's recommended parameters, `POST /session` answers the `fitcher_session` cookie (`HttpOnly`, `SameSite=Strict`, `Secure` over HTTPS) and `DELETE /session` ends it; a session is a random 32-byte id stored only as its SHA-256 and ends after 12 hours idle, 30 days in all, on sign-out, on a password reset and when the account is disabled; five failed sign-ins for one e-mail or twenty from one address within 15 minutes answer 429 with `Retry-After`, and a failure never says whether the account exists. Until the web app leaves Keycloak, a request without the cookie may still send a Keycloak bearer token.
- Connect models in the application: the setup gains a Models step that adds a provider (with the `host.docker.internal` hint for a model server on the host), runs its test call labelled as paid for a hosted provider and shows the proposed model of each tier, and adding a provider answers the step. The console's Models page lists the providers with the last four characters of their key, adds, tests, re-keys and removes them, maps each tier to any model of a configured provider next to the pack's latest eval result for it (`GET /models/tiers` now reports it; it never gates the choice), changes the embedding only after confirming the reindex, and turns the screening classifier on and off. The web server forwards these through `/api/providers`, `/api/models` and `/api/screening`, and their types are generated from the api's contracts.
- Embed pack content with a connected provider's embedding model, or locally when none offers one: adding a provider proposes its embedding model (OpenAI `text-embedding-3-large` at 1024 dimensions, Gemini `gemini-embedding-001` at 768, Ollama `nomic-embed-text` at 768), because `docs/eval/local-embedding-report.md` measured that both local candidates lose retrieval recall against it, most in Vietnamese; `app/llm/local_embeddings.py` runs `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (384 dimensions, or `paraphrase-multilingual-mpnet-base-v2`, 768) with fastembed on CPU when no provider offers one or an admin chooses it, downloaded on first use into `<FITCHER_DATA_DIR>/models`. The `llm.embedding` setting records the backend, model and dimensions; `PUT /models/embedding` changes it only with `confirm_reindex`, and `GET /models/tiers` reports `needs_reindex` while the active pack was indexed with another model. A pack compiled before the app state existed keeps its embedding model when bootstrap creates its provider. `fastembed==0.9.1` is added and `huggingface-hub` moves from 2.4.0 to 1.33.0, which fastembed requires.
- Add the provider endpoints for an `admin`: `GET`, `POST`, `PATCH` and `DELETE /providers` (a provider a tier or the embedding uses cannot be removed), `GET /providers/{id}/models` from each provider's own model list, `POST /providers/{id}/test` (lists the models, then asks one model for a small structured reply and says whether that call is billed; a model that fails structured output stays selectable), `GET /models/tiers` and `PUT /models/tiers/{tier}` with `{provider_id, model}` for the chat tiers. - Keep model providers and the tier mapping in the app state: a `providers` table (state change `0004_providers.sql`) holds each OpenAI, Anthropic, Gemini, Ollama or OpenAI-compatible provider with its name and base URL, its key goes into the vault as `provider:<id>:api_key`, and settings `llm.tiers` and `llm.embedding` map every chat tier to any model of a configured provider and the embed tier to a model and vector size.
