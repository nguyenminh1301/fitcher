# Phase 9D: Model routing

## Goal

Spend the large models only where a question needs them (DECISIONS §2 Model tiers, §6): a deterministic complexity rule sends simple query specs to the `sql-small` tier and escalates on failure, the LiteLLM catalog offers models from several providers behind their own aliases, an alias becomes eligible for a tier only after the pack eval passes with it, and an `admin` maps the chat tiers to eligible aliases on a Models page of the console.

## Scope

- The complexity rule and tier choice in `generate_sql`, with escalation in `check`.
- Tier names in the engine and a tier-to-alias mapping read at run time, with defaults from `.env`.
- A LiteLLM catalog with OpenAI, Anthropic, Gemini and a local model served by Ollama.
- Eval runs with a tier override, and eligibility recorded per pack, tier and alias.
- The Models API and console page for an `admin`, and the tier on every `llm_calls` row.

## Out of scope

- Routing by an LLM classifier; the rule stays deterministic.
- Choosing a model per question by the user in the chat.
- Changing the `embed` tier from the console (a new embedding model needs a full reindex).
- Fine-tuning or hosting models other than through Ollama.

## Prerequisites

- Phases 4, 5 and 7: eval harness, `llm_calls` logging, the api with Keycloak roles.
- Provider keys in `.env` for each provider the owner enables; the local model needs the `local-models` Compose profile.

## Tasks

1. **Complexity rule (test first).** A pure function over the QuerySpec: simple when it has one metric, at most one dimension, one period, no comparison, no top N and one dataset (DECISIONS §14); everything else is standard. Tests on every condition and on the pack eval specs.
2. **Tier choice and escalation (test first).** `generate_sql` uses `sql-small` for a simple spec and `sql-gen` otherwise; after a failed `sql-small` attempt the next attempt uses `sql-gen`, and the third retry keeps `sql-gen-hard`. The chosen tier goes into the run's events and the LiteLLM metadata. Tests with the scripted fake client cover each path.
3. **Catalog.** One alias per offered model, named for provider and size (for example `openai-small`, `anthropic-medium`, `gemini-small`, `local-small`), keys from `.env`; an alias whose key is missing is not loaded. Structured-output support is checked per alias by a smoke job that makes one tiny billable call per alias.
4. **Mapping store.** `data_meta.model_tiers(tier, alias, changed_by, changed_at)` as a ReplacingMergeTree written by a dedicated user; the api reads it with a cache of at most 30 seconds and falls back to the `.env` defaults, so a change needs no LiteLLM restart.
5. **Eligibility (test first).** `jobs/eval.py --tier <tier>=<alias>` runs the pack eval with that override and stores the mapping in the report; an alias is eligible for a tier when its latest report for the pack meets the threshold and does not regress against the baseline (DECISIONS §14).
6. **Models API (test first).** `GET /admin/models` lists tiers with the current alias, provider, eligibility and the report that enabled it; `PUT /admin/models/{tier}` (`admin` only) accepts only an eligible alias for a chat tier, refuses `embed`, and writes `admin_actions`. Tests use a fake store.
7. **Models page.** A console section for `admin` that lists the tiers and lets the admin pick an eligible alias, showing why an ineligible alias is disabled.
8. **Costs by tier.** `llm_calls` gains a `tier` column filled from the request metadata; the Costs view (Phase 12) groups by tier and provider.
9. **Measure.** Run the pack eval with routing on and report the share of SQL generated by `sql-small`, the escalation rate and the cost per answered question against the baseline.

## Contracts

- Tier names: `fast`, `sql-small`, `sql-gen`, `sql-gen-hard`, `embed`.
- `GET/PUT /admin/models` payloads; `data_meta.model_tiers`; `llm_calls.tier`.
- Settings: `MODEL_TIER_<TIER>` defaults; provider keys `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`; `OLLAMA_URL`.

## Definition of done

| DoD item | Proof |
|---|---|
| Routing on does not regress the pack eval | Eval report against the baseline, with the `sql-small` share |
| An ineligible alias cannot be assigned | Models API test and page behaviour |
| A tier change takes effect without a LiteLLM restart and is audited | Integration test reading the new alias within the cache window; `admin_actions` row |

## Risks and open questions

1. **Provider differences.** Structured output, temperature and token limits differ between providers. Default: an alias is offered only after the task 3 smoke call succeeds and the task 5 eval passes.
2. **Missing keys.** LiteLLM may refuse to start when a referenced environment variable is unset. Default: the catalog is generated from the keys present, or each provider block is kept in a separate included file.
3. **Local model weight.** Ollama models need RAM and disk. Default: the `local-models` profile is optional and off by default.
4. **Rule too narrow or too wide.** Default: start with the DECISIONS §14 rule and widen it only when the eval shows no regression.
